# LOLGuess.gg

Wordle-style игра на угадывание чемпионов League of Legends.

🔗 [Демо](https://my3blka.github.io/LoLguess/)
📦 [Репозиторий](https://github.com/My3blKa/LoLguess)

## Стек

Vanilla JS (ES6 классы), SCSS (BEM), без фреймворков и сборщиков

## Режимы

- **Classic Daily** — готово. Один чемпион в сутки, сброс по UTC
- **Classic Endless** — готово. Бесконечный режим со случайным чемпионом и сессией
- Quote / Ability / Splash Art — в разработке
- i18n (RU/EN) — переключатель есть визуально, смена языка контента не реализована

## Classic Daily — базовая механика

- Дропдаун с живым поиском, навигация стрелками, выбор кликом/Enter
- Сравнение чемпиона по 7 полям (пол, позиции, виды, ресурс, тип атаки,
  регионы, год) — с разной логикой для строк, массивов и дат
- Анимация появления результатов построчно
- Чемпион дня выбирается детерминированно по UTC-дате (дни с эпохи %
  количество чемпионов) — у всех игроков одинаковый чемпион в сутки
- Сброс прогресса привязан к UTC, а не локальному времени — иначе не
  совпадает между часовыми поясами
- 3 подсказки (цитата/спелл/сплэш), разблокируются по числу попыток; сама
  подсказка фиксируется в localStorage, чтобы не менялась при перезагрузке
- Обратный отсчёт до следующего чемпиона (полночь UTC)

## Технические детали

### Изоляция состояния между режимами

Endless изначально был копией Daily — включая ключи localStorage. Из-за этого
прогресс одного режима перезаписывал прогресс другого. Решили через
namespaced-ключи (`classicDaily*` / `classicEndless*`).

### Персистентность раунда в Endless

Чемпион выбирается случайно и должен переживать перезагрузку страницы, пока
раунд активен. Храним его `championId` в localStorage, обновляем только по
истечении таймаута сессии (45 минут через `Date.now()`) или по кнопкам
"сдаться"/"ещё раз".

### Гонка при инициализации классов

`Hints` изначально читал данные о загаданном чемпионе из localStorage прямо
в конструкторе — раньше, чем асинхронный `getChampionsData()` в `Guess`
успевал их туда записать. Убрали чтение из `Hints`, данные теперь передаются
параметрами методов из `Guess`, который ими и владеет.

### Разделение ответственности между классами

Логика подсказок (`setQuoteHint` и т.д.) сначала жила в `Guess`, хотя по
смыслу принадлежала `Hints` — просто `Hints` не имел доступа к данным
чемпиона. Вернули методы в `Hints`, но теперь они принимают данные
параметром, а не тянутся за ними сами.

## Сильные стороны реализации

- Осознанно пойманная и исправленная гонка при инициализации: `Hints`
  читал данные о чемпионе из localStorage раньше, чем асинхронный
  `getChampionsData()` в `Guess` успевал их записать
- Сброс ежедневного прогресса привязан к UTC, а не к локальному времени —
  иначе дата "сбрасывалась" бы в разное время для игроков в разных
  часовых поясах
- Архитектура пересматривалась по ходу: логика подсказок сначала лежала
  не в том классе, была перенесена обратно в `Hints` с переходом на
  параметры вместо прямого чтения состояния
- В localStorage сохраняется только `championId`, а не весь объект
  чемпиона — сам объект восстанавливается поиском в уже загруженном
  датасете, без дублирования данных
- Общий метод сброса раунда (`resetRound`) переиспользуется в трёх разных
  местах — по таймауту сессии, по кнопке "сдаться" и по кнопке "ещё раз" —
  вместо копирования одной и той же логики
- Восстановление состояния после перезагрузки страницы и обработка живого
  ввода идут через один и тот же метод проверки ответа, а не дублируют
  логику в двух местах
- Сравнение 7 характеристик чемпиона реализовано через конфигурацию с
  разделением по типу данных (строка/массив/дата) — одна и та же функция
  сравнения обрабатывает все поля без дублирования логики под каждое из них
